# Сертификаты и бонусы

Подарочные сертификаты и программа лояльности для малого бизнеса: салона,
барбершопа, студии, кофейни. Бизнес заводит витрину, печатает один код на стойку
и дальше работает без приложений, регистраций и анкет.

Демо: https://b-on-g.github.io/sert/

## Как это работает

**У бизнеса** есть кабинет и адрес витрины вида `/bz=<ленд>` или
`/bzname=coffier_shopper`. Код витрины печатается и кладётся на стойку.

**Гость** сканирует код телефоном, открывает витрину и жмёт «Завести карту».
Ничего не заполняет: карта заводится в его же браузере и не спрашивает ни имени,
ни почты, ни телефона. У карты есть свой QR — его гость и показывает на кассе.

**Кассир** открывает раздел «Касса», наводит камеру на карту гостя, вводит сумму
чека и начисляет. Списание оттуда же.

## Почему сканирует касса, а не гость

Соблазн сделать наоборот велик: повесить код на стойку, и пусть гость сканирует
и сразу получает баллы. Но такой код — ферма: его отсканируют сто раз и перешлют
знакомым.

Поэтому два действия разведены, и накрутка исчезает без единой проверки.

**Знакомство** остаётся самообслуживаемым: код на стойке статический, сканируй
сколько хочешь. Заведение карты **не начисляет ничего**, так что плодить карты
бессмысленно.

**Начисление** делает только касса, своим ключом, в книгу операций салона. Гость
писать в эту книгу не вправе, поэтому подделать баланс ему нечем. Приветственный
бонус тоже даёт кассир, и только если по карте ещё не было ни одной операции.

## Устройство

| Модуль | Что делает |
| --- | --- |
| `cert/` | схема сертификата и чистые форматтеры |
| `shop/` | схема салона: реквизиты, сертификаты, книга операций |
| `pass/` | схема карты гостя |
| `op/` | схема операции и весь счёт баллов |
| `home/` | указатели в домашнем ленде: свой салон и своя карта |
| `name/` | реестр коротких имён витрин |
| `page/` | база страниц кабинета |
| `desk/` | кабинет: `$mol_book2_catalog` с семью разделами |
| `front/` | витрина салона |
| `card/` | карта гостя с QR и балансами |
| `sheet/` | бланк сертификата |
| `area/` | многострочное поле |
| `app/` | оболочка и разбор адреса |

### Кто что пишет

Салон живёт в **своём** ленде с чтением для всех: домашний ленд владельца для
витрины не годится. Указатель на салон лежит в домашнем ленде рядом со списком
всех заведённых — указатель перетирается последней записью, а список сливается,
и на холодном старте второе устройство иначе заведёт себе второй салон.

Каждый сертификат получает свой ленд: ссылка на него и есть предъявитель.

Карту гостя заводит **гость**, в своём ленде. Салон в неё не пишет ничего.
Баллы лежат в книге операций салона, карта их только складывает.

Операции кладутся прямо в ленд салона через `make( null )`, а не отдельными
лендами: отдельный ленд стоит доказательства работы, и касса ждала бы секунды
на каждом чеке.

### Про короткие имена

Имя это удобство, а не собственность. Реестр общий, писать в него может кто
угодно с доказательством работы, а время записи ставит её же автор — заявку
задним числом запретить некому.

Поэтому всё ценное ссылается на ленд, а не на имя: и сертификат, и карта, и
печатный код на стойке. Перехват имени ломает вход на витрину и ничего больше.
Когда на имя есть несколько заявок, приложение показывает выбор, а не угадывает.

## Разработка

```bash
cd /path/to/mam && npm start
# http://localhost:9080/bog/sert/app/-/index.html
```

Проверять именно `index.html`: `-/test.html` прибивает мастера синхронизации к
`localhost:9090`. Роутер по путям на `/-/` отключён намеренно, поэтому адреса
там хешевые.

```bash
npx mam bog/sert/app             # сборка
cat bog/sert/app/-/web.audit.js  # должен быть пустым
node bog/sert/app/-/node.test.js # тесты
```

## Деплой

Пуш в `main` собирает бандл и кладёт его на GitHub Pages. Ветки `feature/*`
уезжают в подпапку с тем же именем. В собранную папку кладётся `404.html`:
Pages отдаёт его на любой неизвестный путь, а он возвращает адрес в приложение.

## Чего пока нет

- Отдельные права для сотрудников: и гашение, и касса привязаны к ключу владельца.
- Защиты от двойного гашения и двойного начисления офлайн.
- Книга операций салона читается целиком и публично: видно число гостей и ритм
  начислений, хотя имён там нет. Лечится отдельным лендом на гостя.
- Логотипа салона и печатной вёрстки сертификата.
