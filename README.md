# Сертификаты

Подарочные сертификаты на свои услуги для малого бизнеса: салона, барбершопа,
студии, фотографа, школы. Менеджер заполняет карточку, отправляет её получателю
готовым письмом и гасит при визите.

Демо: https://b-on-g.github.io/sert/

## Чем это отличается от площадок вроде Digift

Площадки продают чужие бренды и держат деньги у себя, поэтому им нужны договоры
с магазинами, расчётный центр и аккаунт-менеджер. Здесь эмитент сертификата и
есть клиент: он дарит собственную услугу, деньги берёт как берёт и так, а
приложение отвечает только за выпуск, учёт и гашение.

Из этого следуют три вещи, ради которых всё и затевалось.

**Персональных данных получателей на сервере нет.** Ленды зашифрованы, ключ
лежит в браузере владельца. Рассылку делает сам салон своими средствами, база
почт остаётся у него.

**Гашение работает офлайн.** Ленд сертификата — CRDT, поэтому администратор в
подвале без связи отмечает сертификат использованным, а синхронизация догоняет
позже. Обратная сторона: два администратора офлайн могут погасить один и тот же
сертификат, и конфликт вскроется только при слиянии.

**Хостинга под клиента нет.** Статика на GitHub Pages плюс общий узел
Гипер Базы.

## Как устроено

| Модуль | Что делает |
| --- | --- |
| `cert/` | схема сертификата и чистые форматтеры (текст письма, состояние) |
| `shop/` | схема салона: реквизиты и реестр выпущенного |
| `desk/` | кабинет: реквизиты, форма выпуска, список |
| `desk/row/` | строка реестра |
| `card/` | карточка сертификата: то, что видит получатель |
| `key/` | перенос ключа доступа между устройствами |
| `app/` | оболочка и разбор адреса |

Салон лежит в домашнем ленде владельца. Каждый сертификат получает **свой** ленд
с правом чтения для всех: ссылка на него и есть предъявитель, как номер на
бумажном сертификате. Поэтому в сертификат копируются название салона и его
контакты — получателю не нужен доступ к ленду салона, чтобы прочитать карточку.

Гасить может тот, у кого есть право записи в ленд сертификата, то есть владелец
ключа. Чтобы гасить с планшета на ресепшене, ключ переносят через раздел «Ключ».

## Разработка

```bash
cd /path/to/mam && npm start
# http://localhost:9080/bog/sert/app/-/index.html
```

Проверять именно `index.html`: `-/test.html` прибивает мастера синхронизации к
`localhost:9090`, и синхронизация с общим узлом не проверяется.

```bash
npx mam bog/sert          # сборка
cat bog/sert/app/-/web.audit.js   # должен быть пустым
node bog/sert/app/-/node.test.js  # тесты
```

## Деплой

Пуш в `main` собирает бандл и кладёт его на GitHub Pages. Ветки `feature/*`
уезжают в подпапку с тем же именем.

Роутер работает по путям, поэтому в собранную папку кладётся `404.html` —
GitHub Pages отдаёт его на любой неизвестный путь, а он возвращает адрес назад
в приложение.

## Чего пока нет

- Отдельные права для сотрудников: гашение привязано к ключу владельца.
- Ограничения на двойное гашение офлайн.
- Логотип салона на карточке.
- Печатная версия сертификата.
